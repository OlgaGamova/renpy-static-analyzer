# Тестирование производительности RenPy Static Analyzer

Этот документ описывает инфраструктуру для тестирования производительности системы статического анализа RenPy.

## Обзор

Инфраструктура тестирования производительности включает:

1. **Генератор тестовых сценариев** - создает большие сценарии RenPy с контролируемыми параметрами
2. **Бенчмарк** - замеряет время выполнения каждого этапа анализа
3. **Автоматический раннер** - запускает все тесты последовательно

## Файлы

- `tests/generate_performance_scenarios.py` - генератор сценариев
- `tests/performance_benchmark.py` - бенчмарк производительности
- `run_performance_tests.py` - скрипт для запуска всех тестов
- `tests/samples/performance/` - директория для сгенерированных сценариев
- `tests/results/performance/` - директория для результатов бенчмарков

## Быстрый старт

### Способ 1: Автоматический запуск (рекомендуется)

```bash
python run_performance_tests.py
```

Этот скрипт:
1. Сгенерирует набор тестовых сценариев разного размера
2. Запустит бенчмарки на всех сценариях
3. Сохранит результаты в JSON

## Что измеряется

Бенчмарк замеряет время выполнения каждого этапа:

1. **Парсинг** - парсинг текста сценария с помощью Lark
2. **Трансформация** - преобразование AST в IR (Intermediate Representation)
3. **Построение графа** - создание графа переходов между label'ами
4. **Анализ достижимости** - поиск недостижимых узлов (DFS)
5. **Анализ мертвых концов** - поиск терминальных узлов
6. **Анализ бесконечных циклов** - поиск SCC алгоритмом Тарьяна
7. **Анализ состояния** - анализ переменных и условий

## Интерпретация результатов

### Ожидаемая производительность

| Размер сценария | Узлы | Ожидаемое время |
|-----------------|------|-----------------|
| Маленький | 50-100 | < 0.5с |
| Средний | 250-500 | < 2с |
| Большой | 1000-2000 | < 10с |
| Очень большой | 5000 | < 60с |

### Потенциальные проблемы

#### 1. Очень медленный парсинг (> 5с для 500 узлов)
**Причина:** Lark парсер может медленно работать с очень большими файлами
**Решение:**
- Рассмотреть использование парсера `earley` вместо `lalr` для сложных грамматик
- Оптимизировать грамматику
- Разбивать большие сценарии на модули

#### 2. Медленный анализ состояния (> 10с)
**Причина:** Анализ состояния использует BFS с копированием состояний, что может создавать экспоненциальное количество путей
**Решение:**
- Ограничить глубину анализа
- Использовать более эффективные структуры данных
- Применить memoization для повторяющихся состояний
- Реализовать incremental analysis

#### 3. Переполнение стека (RecursionError)
**Причина:** Рекурсивный DFS в анализе достижимости и алгоритме Тарьяна
**Решение:**
- Преобразовать рекурсию в итеративный обход с использованием стека
- Увеличить лимит рекурсии: `sys.setrecursionlimit(10000)`

#### 4. Высокое потребление памяти
**Причина:** Хранение всех путей в анализе состояний
**Решение:**
- Ограничить длину сохраняемых путей
- Использовать более компактные структуры данных
- Применить garbage collection

## Генерация пользовательских сценариев

### Пример использования генератора

```python
from tests.generate_performance_scenarios import RenPyScenarioGenerator

# Генерация случайного сценария
generator = RenPyScenarioGenerator(seed=42)

script = generator.generate_scenario(
    num_nodes=1000,           # количество узлов
    branching_factor=3,       # среднее количество вариантов в menu

    output_path="my_scenario.rpy"

# Генерация линейного сценария
script = generator.generate_linear_scenario(
    num_nodes=500,
    output_path="linear_scenario.rpy"
)

# Генерация глубокого дерева
script = generator.generate_deep_tree_scenario(
    depth=20,
    branching=2,
    output_path="deep_tree.rpy"
)
```

## Настройка бенчмарка

### Программное использование

```python
from tests.performance_benchmark import PerformanceBenchmark

benchmark = PerformanceBenchmark(output_dir="my_results")

# Запуск на одном файле
result = benchmark.run_benchmark("tests/samples/performance/perf_500.rpy")

# Запуск на нескольких файлах
results = benchmark.run_benchmarks([
    "tests/samples/performance/perf_500.rpy",
    "tests/samples/performance/perf_1000.rpy"
])

# Вывод сводки
benchmark.print_summary()

# Сохранение результатов
benchmark.save_results("my_benchmark.json")
```

## Устранение проблем

### Сценарий не генерируется
- Проверьте права на запись в директорию `tests/samples/performance/`
- Убедитесь, что有足够的 свободного места на диске

### Бенчмарк падает с ошибкой
- Проверьте, что все зависимости установлены: `pip install -r requirements.txt`
- Запустите с флагом `--scenarios` для тестирования на конкретном файле
- Проверьте логи ошибок в выводе бенчмарка

### Слишком долгое выполнение
- Начните с маленьких сценариев (`--scenarios tests/samples/performance/perf_small_50.rpy`)
- Проверьте, нет ли бесконечных циклов в анализе состояния
- Рассмотрите ограничение размера сценариев
